# 代码审查规范

## 目的

代码审查确保代码在合并前具备应有的质量、安全性与可维护性。本规则定义了何时以及如何进行代码审查。

## 审查时机

**强制触发审查：**

- 编写或修改代码之后
- 向共享分支提交任何代码之前
- 当修改安全敏感代码时（认证、支付、用户数据）
- 发生架构变更时
- 合并拉取请求之前

**审查前置要求：**

请求审查前，确保：

- 所有自动化检查（CI/CD）已通过
- 合并冲突已解决
- 分支已与目标分支同步

## 审查清单

在标记代码完成之前：

- [ ] 代码可读且命名良好
- [ ] 函数聚焦（<50 行）
- [ ] 文件内聚（<800 行）
- [ ] 没有深度嵌套（>4 层）
- [ ] 错误被显式处理
- [ ] 没有硬编码的密钥或凭证
- [ ] 没有 console.log 或调试语句
- [ ] 新功能有对应测试
- [ ] 测试覆盖率达到最低 80%

## 安全审查触发条件

**遇到以下情形应立即停下来并使用 security-reviewer agent：**

- 认证或授权代码
- 用户输入处理
- 数据库查询
- 文件系统操作
- 外部 API 调用
- 加密操作
- 支付或财务代码

## 审查严重性级别

| 级别 | 含义 | 操作 |
|-------|---------|--------|
| CRITICAL | 安全漏洞或数据丢失风险 | **阻断** — 合并前必须修复 |
| HIGH | Bug 或显著质量问题 | **警告** — 合并前应当修复 |
| MEDIUM | 可维护性问题 | **提示** — 建议修复 |
| LOW | 风格或细节建议 | **备注** — 可选 |

## Agent 使用

使用以下 agent 进行代码审查：

| Agent | 用途 |
|-------|---------|
| **code-reviewer** | 通用代码质量、模式、最佳实践 |
| **security-reviewer** | 安全漏洞、OWASP Top 10 |
| **typescript-reviewer** | TypeScript/JavaScript 相关问题 |
| **python-reviewer** | Python 相关问题 |
| **go-reviewer** | Go 相关问题 |
| **rust-reviewer** | Rust 相关问题 |

## 审查工作流

```
1. 运行 git diff 理解变更
2. 先检查安全清单
3. 再检查代码质量清单
4. 运行相关测试
5. 验证覆盖率 >= 80%
6. 使用合适的 agent 进行深入审查
```

## 需要捕捉的常见问题

### 安全

- 硬编码凭证（API 密钥、密码、令牌）
- SQL 注入（查询中的字符串拼接）
- XSS 漏洞（未转义的用户输入）
- 路径穿越（未净化的文件路径）
- 缺少 CSRF 保护
- 认证绕过

### 代码质量

- 大函数（>50 行）— 拆分为更小的函数
- 大文件（>800 行）— 抽取模块
- 深度嵌套（>4 层）— 使用早返回
- 缺少错误处理 — 显式处理
- 可变模式 — 优先使用不可变操作
- 缺少测试 — 增加测试覆盖

### 性能

- N+1 查询 — 使用 JOIN 或批处理
- 缺少分页 — 为查询增加 LIMIT
- 无界查询 — 增加约束
- 缺少缓存 — 为耗时操作增加缓存

## 通过标准

- **通过**：没有 CRITICAL 或 HIGH 问题
- **警告**：仅有 HIGH 问题（合并需谨慎）
- **阻断**：发现 CRITICAL 问题
