# 构建与修复

以最小、安全的改动逐步修复构建错误和类型错误。

## 第 1 步：检测构建系统

识别项目使用的构建工具并运行构建：

| 指标 | 构建命令 |
|-----------|---------------|
| `package.json` 中含 `build` 脚本 | `npm run build` 或 `pnpm build` |
| `tsconfig.json`（仅 TypeScript） | `npx tsc --noEmit` |
| `Cargo.toml` | `cargo build 2>&1` |
| `pom.xml` | `mvn compile` |
| `build.gradle` | `./gradlew compileJava` |
| `go.mod` | `go build ./...` |
| `pyproject.toml` | `python -m compileall -q .` 或 `mypy .` |

## 第 2 步：解析并分组错误

1. 运行构建命令并捕获 stderr
2. 按文件路径对错误进行分组
3. 按依赖顺序排序（先修复 import/类型错误，再修复逻辑错误）
4. 统计错误总数以便跟踪进度

## 第 3 步：修复循环（每次只修一个错误）

对每一个错误：

1. **读取文件** —— 使用 Read 工具查看错误上下文（错误位置前后 10 行）
2. **诊断** —— 识别根本原因（缺失 import、类型不对、语法错误）
3. **最小化修复** —— 使用 Edit 工具进行能解决该错误的最小改动
4. **重新运行构建** —— 验证错误已消除且未引入新的错误
5. **继续下一个** —— 处理剩余错误

## 第 4 步：护栏（Guardrails）

遇到以下情况时，停止并询问用户：

- 某次修复**引入的错误比解决的还多**
- **同一个错误连续尝试 3 次仍无法解决**（通常意味着更深层的问题）
- 修复需要**架构层面的改动**（而非单纯的构建修复）
- 构建错误源于**缺失依赖**（需要 `npm install`、`cargo add` 等）

## 第 5 步：总结

展示结果：

- 已修复的错误（附文件路径）
- 剩余的错误（如有）
- 新引入的错误（应为零）
- 对未解决问题的后续建议

## 恢复策略

| 情境 | 应对措施 |
|-----------|--------|
| 缺失模块 / import | 检查依赖包是否已安装；给出安装命令建议 |
| 类型不匹配 | 阅读两侧的类型定义；修正更窄的那一侧 |
| 循环依赖 | 通过 import 图识别环；建议抽取共享部分 |
| 版本冲突 | 检查 `package.json` / `Cargo.toml` 中的版本约束 |
| 构建工具配置错误 | 阅读配置文件；与能正常工作的默认配置对比 |

一次只修一个错误以确保安全。优先选择最小 diff，而非顺手重构。
